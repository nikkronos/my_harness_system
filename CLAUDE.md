# CLAUDE.md — рабочая область · вход для агента

> Этот файл Claude Code читает автоматически при старте. Это **ВХОД** в систему:
> отсюда агент понимает, кто владелец, где «сейчас», где правила и как работать.
>
> 🛠️ СТАРТОВЫЙ ШАБЛОН. Места `<— ... —>` замени под себя (или попроси агента помочь).

## Что это за система

Единая рабочая область: проекты + документация + правила работы с агентом.
Цель — чтобы любой агент (Claude Code и др.) с первого захода был **ориентирован**,
а не начинал с нуля каждый раз.

## Четыре якоря (как ориентироваться)

| Якорь | Что это | Где |
|---|---|---|
| **ВХОД** | начни отсюда | этот `CLAUDE.md` |
| **СОСТОЯНИЕ** | кто владелец + что сейчас в работе | `Main_docs/PROFILE.md`, `Main_docs/PROJECTS.md` |
| **ПРАВИЛА** | как работать, чего нельзя | `Main_docs/RULES.md` |
| **ПРОЕКТЫ** | где код/задачи, читать по запросу | `Main_docs/PROJECTS.md` + сами проекты |

## Старт сессии (что делает агент)

1. `git status` и `git log --oneline -3`.
2. Прочитать этот файл (ВХОД).
3. Прочитать `Main_docs/PROFILE.md` (кто владелец, как с ним работать).
4. По задаче — найти проект в `Main_docs/PROJECTS.md`, открыть его файлы.
5. Перед первой правкой — короткий план. После согласования — автономно до
   проверки, документации и коммита. Полный цикл завершения — `Main_docs/RULES.md`.

## Навигация (против перегруза контекста)

- Длинные документы **не читать целиком** — прыгать к нужной секции по оглавлению.
- Держать **СОСТОЯНИЕ** коротким; историю и детали уводить в отдельные файлы.
- Слабая карта/оглавление — сначала починить карту, потом работать.

## Структура

```text
<рабочая область>/
├── CLAUDE.md          # этот файл — вход
├── Main_docs/         # PROFILE (кто), RULES (как), PROJECTS (где)
└── Projects/          # твои проекты   <— заведи по необходимости —>
```

## Git-границы

В одной рабочей области может быть несколько Git-репозиториев. Перед изменениями
и коммитом — не угадывать корень по папке:

```
git rev-parse --show-toplevel
git status
git remote -v
```

Секреты (`.env`, токены, ключи, session-файлы) — **не коммитить** (защита в `.gitignore`).

## Завершение

Проверить diff → тесты/линтер → обновить затронутую документацию → проверить
Git-root → коммитить и пушить только проверенное. Подробно — `Main_docs/RULES.md`.
