# My Harness System — стартовая система для работы с AI-агентом

_Обновлено: 27.07.2026_

Готовый каркас рабочей области для Claude Code и совместимых агентов: структура
папок и файлы-правила, из которых агент сразу понимает, кто владелец, какие есть
проекты и как работать.

Это **обезличенный шаблон реальной рабочей системы**: скачиваешь, агент задаёт
несколько вопросов и заполняет его под тебя. Дальше каждый новый чат стартует
уже «в курсе», а не с нуля. Личных данных и секретов в шаблоне нет.

## Два слоя, и главный — не тот, о котором думают

**Личный слой (`KB/`)** — кто ты и что у тебя вокруг: чем занят, что важно, чего
нельзя, что уже пробовал. Приватный, в git не уходит никогда.

**Обвязка (всё остальное)** — правила, структура, замок на секреты. Она нужна не
сама по себе, а чтобы агент не переучивал твою биографию в каждом новом чате.

Порядок именно такой: сначала знание о человеке, потом механика вокруг него.
Шаблон без личного слоя — это просто аккуратные папки. AI полезен ровно
настолько, насколько он в курсе реальной жизни, а не абстрактной задачи.

## Что внутри

```text
CLAUDE.md            # вход для Claude Code: агент читает его первым
AGENTS.md            # вход для Codex и других — то же самое, короче
README.md            # этот файл
.gitignore           # секретные файлы не попадут в git
.githooks/           # secret-guard: замок, проверяет содержимое коммита
.gitattributes       # техническая мелочь, чтобы хук работал и на Windows
.claude/commands/    # команды /start и /finish

KB/                  # ЛИЧНОЕ: приватно, в git не уходит         <— создаст агент
Main_docs/
├── PROFILE.md       # КАК с тобой работать: формат, границы       <— заполнит агент
├── RULES.md         # КАК работать: файлы, git, секреты (готово из коробки)
├── PROJECTS.md      # ГДЕ проекты: пути, git, статусы             <— заполнит агент
├── ROADMAP.md       # ГДЕ ТЫ СЕЙЧАС: в работе / дальше / сделано  <— ведёт /finish
├── AGENT_PROMPTS.md # онбординг + готовые prompts на частые задачи
└── KB_GUIDE.md      # что такое личный слой и что в него писать
```

## Правила и замок

Правила в `RULES.md` — это то, что агент **читает**. Обычно он их соблюдает, но
в длинном разговоре может и отвлечься.

Поэтому одна вещь вынесена из правил в код: `secret-guard`. Это скрипт, который
git запускает сам перед каждым коммитом и блокирует его, если внутри нашёлся
API-ключ или токен. Агента он не спрашивает и не зависит от того, прочитал ли
тот инструкцию. Что именно он ловит и чего **не** ловит — честным списком в
`RULES.md`, раздел «Секреты».

Разница с `.gitignore` простая: `.gitignore` прячет файлы **по имени** (`.env` и
подобные). Но если токен вписан прямо в код — имя файла обычное, и `.gitignore`
пропустит. Хук читает **содержимое** и остановит коммит.

Это главный принцип системы: то, что не должно случиться никогда, делается
замком, а не просьбой. Подробнее — раздел «Где что кодировать» в `RULES.md`.

## Две команды: `/start` и `/finish`

Файлы сами себя не заполняют. Чтобы система накапливала знание о тебе, а не
просто лежала, нужны два момента — вход в работу и выход из неё.

**`/start`** — начало сессии. Агент читает, кто ты и как с тобой работать,
поднимает нужный проект и **сначала объясняет, что понял**, а не бросается
менять файлы. Экономит тот самый разговор «нет, я не это имел в виду».

**`/finish`** — конец сессии. Агент проверяет сделанное, **записывает в файлы
всё, что понадобится в следующий раз**, и коммитит.

Вторая важнее. Именно она превращает разговор в память: без неё контекст
остаётся в чате и умирает вместе с ним. Заводить папки бессмысленно, если в них
никто не пишет.

Набирается прямо в чате: `/start почини форму на сайте`, в конце — `/finish`.

## Как развернуть (10–15 минут)

**Вариант 1 — всё делает агент (рекомендуется).**

1. Создай папку под рабочую область (например `Документы\AI_Projects`) и открой
   её в Claude Code. Если у тебя уже есть папка с наработками для агента — можно
   открыть её: агент ничего не затрёт, а покажет найденное и спросит.
2. Скопируй промпт ниже целиком и отправь агенту. Он сам скачает шаблон,
   развернёт его и настроит под тебя.

**Вариант 2 — руками.** Зелёная кнопка **Code → Download ZIP** → распаковать
содержимое в свою папку → открыть папку в Claude Code → отправить тот же промпт
(шаг скачивания агент просто пропустит).

## Промпт для агента (копируй целиком)

```text
Привет! Разворачиваю себе стартовую систему для работы с тобой.
Шаблон: https://github.com/nikkronos/my_harness_system

1. Сначала посмотри, что уже лежит в этой папке. Если найдёшь мои файлы
   для агента (CLAUDE.md, AGENTS.md, .cursorrules, .cursor/, заметки и
   инструкции) — ничего не перезаписывай. Покажи мне список найденного.
2. Скачай файлы шаблона из репозитория и положи содержимое в корень этой
   папки (не во вложенную подпапку). Обязательно перенеси и скрытые папки:
   .githooks (защита от секретов) и .claude (команды /start и /finish) —
   их легко пропустить. Служебную папку .git из шаблона удали: история
   репозитория-шаблона мне не нужна.
   Если файл с таким же именем у меня уже есть — НЕ затирай: сохрани мой
   рядом как <имя>.old и скажи мне об этом.
3. Прочитай README.md и CLAUDE.md — сориентируйся, что это за система.
4. Настрой git: спроси у меня имя и email, пропиши их через
   git config --global, затем сделай git init.
   Аккаунт на GitHub для этого НЕ нужен — всё работает у меня на
   компьютере. Про GitHub не спрашивай: понадобится — попрошу сам.
5. Включи защиту от коммита секретов:
   git config core.hooksPath .githooks
   Затем проверь, что замок реально работает. Создай временный файл со
   строкой, похожей на API-ключ: префикс "sk-" и следом 25 произвольных
   букв и цифр (придумай сам, настоящий ключ не нужен). Добавь файл в
   staged и попробуй закоммитить — коммит должен быть ЗАБЛОКИРОВАН.
   Если он прошёл, скажи мне об этом прямо, не чини молча: значит защита
   не работает. После проверки удали временный файл и сделай первый
   настоящий коммит.
6. Проведи онбординг: открой Main_docs/AGENT_PROMPTS.md, раздел
   «Онбординг владельца», и веди по нему. Сначала спроси, короткий круг
   вопросов или полный, дальше задавай по одному. Ответы разложи по
   файлам так, как сказано в разделе: личное — в KB/owner_profile.md
   (папку KB создай, она вне git), про работу со мной — в
   Main_docs/PROFILE.md, проекты — в Main_docs/PROJECTS.md.
   Если проектов пока нет, так и запиши: система готова к первому.
   В конце покажи короткую выжимку и дай мне её поправить.
7. Разбери мои старые инструкции, если они нашлись на шаге 1: пройди по
   ним со мной и скажи, что стоит перенести в CLAUDE.md, PROFILE.md или
   RULES.md, а что устарело. Решаю я, ты предлагаешь. Если ничего не
   нашлось — спроси, не осталось ли наработок в других AI-инструментах
   (Cursor, Codex, заметки, конфиги).
   Сами проекты и код не трогай — только отметь в PROJECTS.md, где лежат.
8. Запиши в Main_docs/ROADMAP.md, что у меня сейчас в работе и что
   следующее — по моим ответам, без выдумок. Не о чем писать — оставь
   пустым.
9. Проверь, подхватываются ли команды /start и /finish из .claude/commands.
   Если ты не Claude Code — положи оба файла туда, где твой инструмент
   ищет пользовательские команды (у Codex это ~/.codex/prompts/), и
   скажи мне, получилось или нет. Не получилось — объясни, как вызывать
   их вручную.
10. В конце коротко скажи, что готово, и объясни две команды: /start в
   начале работы и /finish в конце. Скажи прямо, что без /finish ничего
   не сохранится между чатами.

Объясняй по ходу простыми словами: возможно, я не из IT.
```

## Частые вопросы

**Это безопасно?** В шаблоне нет ничего личного. Защита от утечки секретов стоит
сразу и в двух слоях: `.gitignore` (по именам файлов) и хук `secret-guard` (по
содержимому коммита). При развёртывании агент проверит, что замок действительно
срабатывает, а не просто лежит в папке.

**У меня нет GitHub и я не знаю, что это.** И не нужно. Git — это программа на
твоём компьютере, которая хранит историю изменений; аккаунт для неё не требуется.
Всё, что делает система, остаётся у тебя локально. GitHub понадобится, только
если ты сам захочешь хранить копию в интернете или показать работу другим —
попросишь агента, он поможет.

**А если у меня уже есть свои файлы для агента?** Агент их не тронет: на первом
шаге он покажет, что нашёл, а при совпадении имён сохранит твой файл рядом с
пометкой `.old`. Дальше вы вместе решите, что перенести, а что выбросить.

**А личное? Я не хочу, чтобы мои дела куда-то ушли.** Папка `KB/` прописана в
`.gitignore` и в репозиторий не попадает — она остаётся у тебя на компьютере.
Пароли и ключи туда всё равно не клади: это обычные файлы на диске. Подробнее —
`Main_docs/KB_GUIDE.md`.

**Хук — это опасно? Он что-то ломает?** Нет. Это обычный текстовый скрипт, он
только читает то, что ты собираешься закоммитить, и в худшем случае говорит
«стоп». Ничего не удаляет и никуда не отправляет. Если он ошибся и мешает —
разовый обход: `git commit --no-verify`.

**У меня не Claude Code, а Codex.** Работает, с двумя оговорками — обе уже учтены
в шаблоне:

- вход. Codex читает `AGENTS.md`, Claude Code — `CLAUDE.md`. Оба файла в шаблоне
  есть, ничего дублировать не надо;
- команды. `/start` и `/finish` лежат в `.claude/commands/`, и Codex туда не
  смотрит: его команды живут в домашней папке `~/.codex/prompts/`. Формат файлов
  совместим, так что достаточно их туда скопировать — агент сделает это на
  последнем шаге развёртывания. Если не вышло, файлы можно просто открыть и
  выполнить как обычную инструкцию.

Замок на секреты работает одинаково везде: это git-хук, он не зависит от того,
каким агентом ты пользуешься.

**Что править руками?** Ничего не обязательно: `PROFILE.md` и `PROJECTS.md`
заполняет агент по твоим ответам, `RULES.md` рабочий из коробки. Но это твоя
система — со временем правь под себя что угодно.
